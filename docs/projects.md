# Каталог рекламных конструкций

Этап «Каталог конструкций» из [TASKS.md](../TASKS.md). Документ фиксирует
текущие продуктовые решения и техническое устройство каталога Noesis.
Хранение файлов описано отдельно в [files-storage.md](./files-storage.md).

## Зафиксированные продуктовые решения

| # | Развилка | Решение |
| - | -------- | ------- |
| 1 | Адрес страницы (slug) | **Заморожен.** При первом сохранении генерируется из названия/кода, дальше сам не меняется. Менеджер может поправить вручную. Коллизии закрываются суффиксом `-2`; уникальность считается по всем записям, включая архив. |
| 2 | «Скоро на сайте» | **Тизер-карточка без публичной страницы.** В каталоге показывается карточка с плашкой «Скоро»; отдельная страница `/constructions/<slug>` не открывается. |
| 3 | Обложка и галерея | **Обложка — одно из фото галереи** (отмечается звёздочкой); порядок задаётся перетаскиванием. Убранное фото удаляется навсегда; удалённая обложка автоматически заменяется первым оставшимся фото. |
| 4 | Координаты | Для публикации конструкции нужны координаты. Они используются публичной Яндекс.Картой; сейчас координаты задаются в настройках карточки вручную. |
| 5 | Цена | Цена за месяц может быть пустой. На публичном сайте пустая цена отображается как «Цена по запросу», заполненная цена показывается в рублях. |
| 6 | Владелец сети | Справочник ведёт admin, менеджер выбирает владельца из списка. Удаление владельца = архивация; записи остаются ради ссылок из конструкций. |
| 7 | Удаление конструкции | **Удаление = архивация**: запись и файлы остаются ради истории заявок, броней и аналитики. Физическое удаление с диска и из БД — только admin. |
| 8 | Обязательные поля | Для обычной публикации нужны название, адрес, владелец сети, формат, сторона, габариты, координаты, описание, обложка и хотя бы одно фото. Черновик можно сохранить с минимальными данными. |
| 9 | Параллельное редактирование | **Блокировка по версии:** при сохранении сверяется `updatedAt`, на котором открыли карточку; если запись успели изменить — 409, правки не затираются молча. |

## Техническое устройство

- **Контракты** (`packages/contracts/src/construction.ts`) — единый источник
  enum'ов, DTO и схемы сохранения: формат, габариты, сторона, подсветка, охват,
  цена, координаты, бейджи, фото и статус публикации.
- **Модели** (Prisma): `Construction`, `ConstructionImage`, `Developer`
  (в UI — «владелец сети»). Обложка задаётся `Construction.coverId`, фото
  хранятся через `Asset`.
- **Сервис** (`backend/src/constructions/`): сохранение — один multipart
  (`data` + новые фото `image_N`). Новые файлы грузятся до записи; при сбое
  транзакции подчищаются; удалённые из галереи фото стираются после коммита.
- **Роуты**: CRM `/api/constructions`, справочник владельцев `/api/developers`,
  публичный каталог `/api/public/constructions`.
- **Публичный сайт**: главная строит карточки из `/api/public/constructions`,
  карточка конструкции живёт на `/constructions/<slug>`, заявки со страницы
  отправляют `constructionId`.
- **Карта**: главная использует Яндекс.Карты, центр по умолчанию — Грозный.
  API-ключ задаётся переменной `PUBLIC_YANDEX_MAPS_API_KEY`; без ключа блок
  показывает понятный фолбэк вместо пустой карты.

## Текущий статус

Каталог конструкций используется в CRM, публичном сайте, документах, фотоотчётах,
бронях, аналитике и заявках. Базовый публичный каталог с картой готов. Следующий
слой — фильтры по формату, цене и занятости на период, а также карта выбора
координат внутри CRM.
