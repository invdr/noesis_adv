> «Жилые комплексы (ЖК) и застройщики» — она сохранена в коде как основа
> будущего каталога **рекламных конструкций** (Этап 1 в [TASKS.md](../TASKS.md)).
> Терминология и поля будут переведены на наружную рекламу (гео, формат,

> текущего кода `Project`/`Developer`.

## Унаследованная модель (ЖК и застройщики)

Этап «Жилые комплексы» из [Вехи 3](../TASKS.md). Ниже — продуктовые решения,
принятые при проектировании (как этим пользуется контент-менеджер), и вытекающее
техническое устройство. Хранение файлов — общий фундамент, см.
[files-storage.md](./files-storage.md).

## Зафиксированные продуктовые решения

| # | Развилка | Решение |
| - | -------- | ------- |
| 1 | Адрес страницы (slug) | **Заморожен.** При первом сохранении генерируется из названия (транслит рус→лат), дальше сам не меняется (переименование ЖК адрес не трогает — старые ссылки и SEO живут). Менеджер может поправить вручную. Коллизии — суффиксом `-2`; уникальность считается по всем записям (вкл. архив), чтобы восстановление не конфликтовало. |
| 2 | «Скоро на сайте» | **Тизер-карточка без страницы.** В каталоге — карточка с плашкой «Скоро» (нужны только название + обложка), отдельная страница `/zhk/<slug>` не открывается. Можно завести с минимумом данных. |
| 3 | Обложка и галерея | **Обложка — одно из фото галереи** (отмечается «звёздочкой»); порядок — перетаскиванием. Убранное фото удаляется навсегда; удалённая обложка → автоматически первое из оставшихся. Мягкий предел — 30 фото на ЖК. |
| 4 | Бейджи | **Палитра фирменных цветов** (из CSS-переменных дизайна), форма как `.badge-soon`; текст ≤24 символов. Цвет — только токен палитры (не произвольная CSS-строка). |
| 5 | Комнатность / цена | Комнатность — **структурно** (студия/1/2/3/4+, на лендинге собирается в строку «Студии, 1–3 комнатные»). Цена «от» — целое ₽, может быть пустой → «Цена по запросу». |
| 6 | Удаление ЖК | **Удаление = архивация** (запись и фото целы — на ЖК ссылаются заявки). Архив/восстановление — manager+admin; «удалить навсегда» (диск + БД) — только admin. |
| 7 | Обязательные поля | **Строгий набор для обычной публикации:** название, адрес, застройщик, цена, комнатность, описание, обложка, ≥1 фото. Черновик — только название; «скоро» — название + обложка. |
| 8 | Параллельное редактирование | **Блокировка по версии:** при сохранении сверяется `updatedAt`, на котором открыли карточку; если запись успели изменить — 409, правки не затираются молча. |

**Застройщик** заведён отдельной сущностью (а не свободным текстом): справочник
ведёт admin, менеджер выбирает из списка. Удаление застройщика = архивация;
удалить навсегда нельзя, пока на него ссылается хотя бы один ЖК.

## Техническое устройство

- **Контракты** (`packages/contracts/src/{project,developer}.ts`) — единый
  источник: enum'ы (`ProjectStatus`, `RoomFormat`), палитра бейджей
  (`BADGE_PALETTE`), хелперы `slugify`/`roomsToLabel`, DTO и схема сохранения
  `upsertProjectSchema` с проверкой обязательности **по состоянию** (через
  `superRefine`, ошибки приходят по конкретным полям формы).
- **Модели** (Prisma): `Developer`, `Project`, `ProjectImage` (упорядоченная
  связь Project↔Asset; обложка — `Project.coverId`, одно из этих фото). Бинарь —
  на диске, в БД метаданные; комнатность/бейджи — JSON-поля.
- **Сервис** (`backend/src/projects/`): сохранение — один multipart (`data` +
  новые фото `image_N`). Порядок гарантирует «ноль сирот»: новые файлы грузятся
  до записи; при сбое транзакции — подчищаются; убранные из галереи фото
  удаляются только после успешного коммита. Slug разрешается по решению №1,
  версия проверяется по решению №8.
- **Роуты**: CRM `/api/projects` (manager+admin; удаление навсегда — admin),
  справочник `/api/developers` (чтение — все, ведение — admin), публичные
  `/api/public/projects` (список опубликованных; страница по slug — без «скоро»).

## Текущий статус

ЖК и застройщики используются в CRM, публичном лендинге, SEO-страницах,
документах, ходе строительства, калькуляторе и заявках. Сохранение публичных
правок помечает сайт как имеющий неопубликованные изменения; вывод на лендинг
происходит после отдельного действия «Опубликовать сайт».
